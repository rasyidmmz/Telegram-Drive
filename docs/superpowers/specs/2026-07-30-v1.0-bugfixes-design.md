# TeleStash v1.0 Bug Fixes & Navigation Alignment Design Spec

## Overview
This design specification addresses five core issues in TeleStash v1.0:
1. **Split-file part pollution**: Legacy split file parts showing up as scattered individual files in folder view.
2. **Unsafe API unwrap**: Potential runtime panic in API sparse fieldset parsing.
3. **MPV title display**: MPV displaying numeric message IDs (e.g., `10`) instead of the actual media file name.
4. **Playlist order & navigation inversion**: Media files playing out of episode order and Next/Prev controls operating in reverse.
5. **Top-left Version Display Inconsistency**: Displaying outdated version strings instead of the active `v1.0.0` version.

---

## 1. Multi-Legacy Split Part Filtering & Manifest Compatibility

### Problem
`cmd_get_files` only checks for caption prefix `[telestash-part]`. Files uploaded in previous versions (TeleDrive / Telegram-Drive) use legacy captions (`[teledrive-part]`, `[telegram-drive-part]`, `[tdrive-part]`, `[tg-part]`). Furthermore, `SplitManifest` deserialization fails if the JSON field was named `teledrive_split`.

### Design & Solution
- **Multi-prefix Guard**: Define a shared helper function `is_split_part_caption(caption: &str) -> bool` checking:
  - `[telestash-part]`
  - `[teledrive-part]`
  - `[telegram-drive-part]`
  - `[tdrive-part]`
  - `[tg-part]`
- **Serde Field Aliases**: Annotate `SplitManifest.telestash_split` with:
  ```rust
  #[serde(alias = "teledrive_split", alias = "telegram_drive_split", alias = "split", alias = "version")]
  pub telestash_split: u8,
  ```
- **Result**: All split parts (legacy & new) are hidden from the folder view, and synthesized single-file movie manifests load seamlessly.

## 2. Unsafe API Fieldsets Fix (`api_routes.rs`)

### Problem
`api_routes.rs:430-445` calls `fields.unwrap().contains(...)` directly on an `Option<Vec<String>>`, which risks panicking if evaluation order or option handling changes.

### Design & Solution
- Replace `fields.unwrap().contains(...)` with `fields.map_or(false, |f| f.contains(...))`.
- **Result**: Safe, non-panicking HTTP API response formatting for sparse fieldsets.

## 3. MPV Media Title Injection

### Problem
When MPV opens stream URLs like `http://localhost:14201/stream/home/10`, MPV displays `10` as the window title and OSD header.

### Design & Solution
- Update `cmd_play_in_mpv` in `app/src-tauri/src/commands/streaming.rs`:
  - When constructing MPV process arguments, inject `--force-media-title=<title>` for single files and for playlist items.
  - Fall back to the document filename if title is absent.
- **Result**: MPV displays `Movie.2024.1080p.mkv` or `Episode 01.mkv` in the OSD and titlebar.

---

## 4. Natural Sort Playlist Order & Directional Navigation Alignment

### Problem
Telegram fetches messages in descending chronological order (newest `message_id` first). Unsorted playlist files order Episode 10 before Episode 1. Clicking Next advances array indices, moving backward in episode order.

### Design & Solution
- **Natural Ascending Sort**: In `MediaPlayer.tsx` (and `DesktopDashboard.tsx`), sort `playlistFiles` using `Intl.Collator` with `{ numeric: true, sensitivity: 'base' }` so files sort naturally (`Ep 01.mkv` -> `Ep 02.mkv` -> `Ep 10.mkv`).
- **Start Index Resolution**: Map `file.id` to the newly sorted array's index before passing `startIndex` to `cmd_play_in_mpv`.
- **Directional Alignment**:
  - `Next` (Right Arrow / `>`) advances to the next episode (e.g., Ep 1 -> Ep 2).
  - `Prev` (Left Arrow / `<`) goes to the previous episode (e.g., Ep 2 -> Ep 1).

---

## 5. Top-Left Version Badge Display & Synchronization

### Problem
The top-left software header currently lacks an explicit version badge, leaving users uncertain if they are running `v1.0.0` or a legacy release.

### Design & Solution
- In `app/src/components/desktop/dashboard/Sidebar.tsx`, import `version` from `package.json` (`v1.0.0`).
- Display a sleek version badge `v1.0.0` right beside the TeleStash brand logo in the top-left sidebar header.
- **Result**: The top-left corner of the software dynamically and prominently displays the exact version (`v1.0.0`).
